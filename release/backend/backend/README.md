# Достижения и звания S10 · бэкенд

Готовый PHP-код достижений атлета и тренера: расчёт по истории, уровни с датами, очки, звания, витрины, согласия учеников и API `/apiweb/achievements.php` по `contract/API.md`. От вас: одна SQL-команда, копирование файлов, один файл с запросами к вашим таблицам и две строки в cron.

PHP 7.4 и новее, PDO, MySQL или MariaDB. Без Composer и без сборки.

## Что сделать

1. **Таблицы.** Выполнить `sql/achievements.sql` в базе сайта. Создаёт 12 таблиц с префиксом `ach_`, существующие таблицы не трогает. Повторный запуск безопасен.

2. **Файлы.**
   - `apiweb/achievements.php` положить в `/apiweb/` сайта, рядом с `userparam.php`.
   - Папки `achievements/` и `cli/` положить рядом друг с другом **вне** папки, которую отдаёт веб-сервер: в каталоге достижений лежат условия секретных. По умолчанию `apiweb/achievements.php` ищет библиотеку на уровень выше корня сайта (`<корень сайта>/../achievements`). Если положили в другое место, поправьте путь в его первой строке.
   - Если папку пришлось положить внутрь корня сайта, закройте её в Angie: `location ^~ /achievements/ { deny all; }`.

3. **Заполнить `achievements/S10Source.php`.** Это единственный файл, который нужно править: в нём методы, которые отдают данные сайта. Что именно вернуть, в каком виде, описано у каждого метода в `achievements/Source.php`. Схемы вашей базы у нас нет, поэтому в методах заготовки запросов с `<tracks>` и подобными: подставьте свои таблицы.

   Обязательные. Пока не заполнены, отвечают ошибкой «not filled in yet»:

   | Метод | Что вернуть | Где это на сайте |
   | --- | --- | --- |
   | `db()` | PDO базы сайта | тот же, что у `/apiweb/*.php` |
   | `currentUserId()` | id из сессии или `null` | как в `/apiweb/*.php` по cookie |
   | `users($ids)` | имена | профиль: `firstName` + `lastName` |
   | `isCoach($id)` | тренер ли | `role` из `/apiweb/student/self/info/` |
   | `athleteIds()`, `coachIds()` | всех атлетов и всех тренеров | для ночного пересчёта |
   | `changedUserIds($since)` | у кого изменились данные после метки времени | `updated_at` треков, дней дневника, planresults, связей с тренером. Можно `[]`, тогда пересчёт раз в сутки |
   | `runs($id)` | пробежки, все источники | треки дневника `/student` → `tracks` с `type: 'run'`. Дубли Strava и Garmin не убирайте, код склеит их сам |
   | `plan($id)` | дни с планом | дневник `/student`: `date`, `type` (typtrain), `target` |
   | `races($id)` | старты | `planresults`: `d`, `distance`, `realhms`, `prehms`, `location`; `main` — целевой старт мастер-плана |
   | `coaches($id)` | периоды атлета с тренерами, только оплаченные | выбор тренера и оплаты |
   | `students($coachId)` | те же периоды со стороны тренера, вместе с ушедшими | то же |

   Необязательные. По умолчанию `null` — значит «на S10 таких данных нет», и зависящие достижения не показываются. Заполните позже — они появятся после ночного пересчёта.

   | Метод или поле | Для каких достижений |
   | --- | --- |
   | `runs`: время старта в `start` | «Жаворонок», «Ночной бегун», «Через полночь» |
   | `runs`: `elev` (набор высоты) | «Эверест», «Горная пробежка», «Эверестинг» |
   | `runs`: `hr_easy` (пульс в 1–2 зоне) | «Восстановление» |
   | `splits` | «Быстрый километр», «Ровный темп» |
   | `masterPlans` | «Цикл до конца», у тренера «До конца» |
   | `reports` | «Отчёт о тренировке» |
   | `ownWeeks` | «Свой план» |
   | `intervals` | «Снайпер» |
   | `challenges` | «Челленджи», «Пьедестал», «Негативный сплит», у тренера «Подиум» |
   | `rating` | «Топ рейтинга» |
   | `tournament` | «Король турнира», у атлета и у тренера |
   | `posts`, `likes`, `comments` | «Автор», «Нравится», «Комментатор» |
   | `clubSince` | «Клубный бегун» |
   | `person` (дата рождения и пол) | «Бостон», у тренера «Уровень учеников» |
   | `replies` (ответы тренера на отчёты) | «На связи» |
   | `forecast` | только подсказка «Прогноз по ПАНО» у рекордов |
   | `isSubscriber` | «Кто видит → Подписчики». Без подписок на сайте это значит «только мой тренер» |

   Проверка: `php cli/check.php --user=ID` покажет, что вернул каждый метод, найдёт ошибки формата и посчитает достижения этого пользователя. В базу ничего не пишет. Запустите на нескольких людях: на себе, на тренере, на новичке.

4. **Пересчёт истории, один раз, на тестовом сервере:** `php cli/recalc.php --history`. Проходит всю историю каждого атлета, потом каждого тренера. Дата уровня — день, когда порог пройден впервые. Поздравления за старые уровни считаются уже показанными, уведомлений нет: никому не придёт сорок окон сразу. Можно прервать и запустить снова, повторный запуск ничего не меняет.

5. **Cron**, пути свои:
   ```
   */5 * * * *  php /srv/s10/cli/worker.php  >> /var/log/s10-achievements.log 2>&1
   30 3 * * *   php /srv/s10/cli/nightly.php >> /var/log/s10-achievements.log 2>&1
   ```
   `worker` раз в 5 минут пересчитывает тех, у кого изменились данные, и их тренеров. `nightly` ночью проходит по всем (серии, месяцы с тренером и всё, что меняется с календарём) и считает редкость уровней. Две копии одновременно не запустятся.

6. **Отчёт для нас:** `php cli/report.php`. Получатся два файла, `achievements-report-ДАТА.md` и `.csv`: сколько людей на каждом уровне каждого достижения и в каждом звании, у атлетов и у тренеров. Пришлите нам оба. Пороги сейчас придуманы, по этим цифрам мы их поправим.

7. **Проверка на тестовом сервере:**
   - `php cli/check.php --user=<свой id>` заканчивается строкой «Ошибок нет».
   - Под своим аккаунтом `/apiweb/achievements.php?action=athlete` отдаёт JSON с `"viewer": "self"`, без входа — `401` и `null`.
   - `?action=athlete&id=<чужой id>` отдаёт `"viewer": "friend"`, у всех `value` — `null`.
   - Под тренером `?action=coach` отдаёт его текущих учеников в `students`.
   - После новой пробежки через 5–10 минут меняется `value` у «Километража».
   - Ошибки пишутся в обычный error_log PHP с пометкой `[achievements]`.

   Пришлите нам ссылку на тестовую версию: страницы мы проверим сами.

## Чего делать не нужно

- Менять код сайта. Ни один существующий файл не меняется, новые только `apiweb/achievements.php`, папки `achievements/`, `cli/` и таблицы `ach_*`.
- Заводить таблицы под каталог. Каталог — JSON-файлы в `achievements/catalog/`, их правим мы.
- Что-то настраивать в `achievements/config.php`: значения по умолчанию рабочие. Подтвердите только код силовой тренировки в typtrain (`strength_type`, сейчас 7).
- Трогать таблицы `data/`: `boston.php` (нормативы Бостона) включится только вместе с датой рождения и полом; `age-grade.php` (возрастные таблицы WMA) мы пришлём отдельно, без него «Уровень учеников» выключен.

## Если нужно снять уровень

Только за накрутку и только вручную: сначала удалите на сайте поддельные тренировки, потом `php cli/revoke.php --user=ID --achievement=km_total --reason="…"`. Запись остаётся в таблице `ach_log`. Иначе уровни не отнимаются никогда, даже если тренировку удалили.

## Тесты и локальный сервер

```
php backend/tests/run.php                          # все тесты, нужен pdo_sqlite; код выхода 1 при ошибке
php -S 127.0.0.1:8090 backend/dev/router.php       # из корня проекта: API на тестовых данных
```

Локальный сервер отдаёт настоящий `/apiweb/achievements.php` на SQLite и синтетических пользователях. Список пользователей и состояний: `http://127.0.0.1:8090/dev/`. Кто вошёл, задаётся `?as=ID` (запоминается в cookie).
